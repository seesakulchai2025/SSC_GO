# ระบบพนักงานสีสกุลไชย

เว็บแอปสำหรับพนักงานยื่นใบลา (ลากิจ ลาป่วย ลาคลอดบุตร ฯลฯ — เพิ่มประเภทเองได้ทั้งหมด) หัวหน้า/แอดมินกดอนุมัติ และติดตามโควตาวันลาแต่ละคน ใช้ได้จากมือถือหรือคอมพิวเตอร์เครื่องไหนก็ได้ผ่านลิงก์เดียว เพราะข้อมูลทั้งหมดเก็บบน Firebase (ไม่ใช่ในเครื่อง)

ล็อกอินด้วย **PIN 4-6 หลัก** (ไม่ต้องใช้อีเมล) เหมาะกับพนักงานที่ไม่สะดวกจำรหัสผ่านยาวๆ

**ฟีเจอร์หลัก**
- ประเภทการลา 3 แบบตายตัว: ลาป่วย (14 วัน/ปี), ลากิจ (7 วัน/ปี), ลาคลอดบุตร (กำหนดโควตาเป็นรายบุคคล)
- ลาได้ทั้งเต็มวันและครึ่งวัน (เช้า/บ่าย) — เลือกได้เมื่อลาวันเดียว
- แนบไฟล์หลักฐาน (รูปภาพ/PDF) ได้ทั้งตอนยื่นใบลาหรือแนบทีหลังก็ได้ — ระบบบีบอัดไฟล์อัตโนมัติแล้วเก็บใน Firestore โดยตรง ไม่ใช้ Firebase Storage จึงไม่ต้องผูกบัตรเครดิต/อัปเกรดแผนใดๆ ทั้งสิ้น ใช้แผนฟรีของ Firebase ได้ 100% (ไฟล์รูปภาพจะถูกย่อขนาดให้เล็กพอสำหรับเก็บ ส่วน PDF ควรมีขนาดไม่เกิน ~500KB)
- ระบบหักวันลาคงเหลืออัตโนมัติเมื่อใบลาได้รับการอนุมัติ
- ปฏิเสธใบลาต้องระบุเหตุผลทุกครั้ง (ระบบบังคับกรอก)
- พิมพ์ใบลาเป็นเอกสาร PDF ได้ (ปุ่ม "พิมพ์ใบลา" ที่แต่ละรายการ → กด "พิมพ์ / บันทึกเป็น PDF" แล้วเลือก "Save as PDF" ในหน้าต่างพิมพ์ของเบราว์เซอร์) เอกสารมีทั้งส่วนลงชื่อผู้ขอลา และส่วนอนุมัติของฝ่ายบริหาร (ผู้ตรวจสอบ/ผู้อนุมัติ) แยกด้วยเส้นประ
- พนักงานลงทะเบียนบัญชีตัวเองได้ (ไม่ต้องรอแอดมินเพิ่มให้) และแก้ไขชื่อ/แผนก/PIN ของตัวเองได้ตลอดเวลาที่เมนู "ข้อมูลของฉัน"
- แอดมินลงบันทึกวันลาแทนพนักงานได้โดยตรง (เมนู "ลงวันลาให้พนักงาน") — รายการที่บันทึกจะถูกอนุมัติทันทีโดยไม่ต้องรออนุมัติซ้ำ
- วันทำการของร้านคือ **จันทร์–เสาร์ หยุดเฉพาะวันอาทิตย์** และระบบ**ดึงวันหยุดราชการ/นักขัตฤกษ์จริงของไทยมาให้อัตโนมัติทุกปี** (จากบริการสาธารณะฟรี Nager.Date ไม่ต้องตั้งค่าอะไรเพิ่ม) แอดมินปรับเปิด/ปิดแต่ละวันได้เองที่เมนู "วันหยุด" — ปิดไว้ = ร้านเปิดตามปกติแม้เป็นวันหยุดราชการ วันที่เปิดใช้งานจะไม่ถูกนับเป็นวันลาโดยอัตโนมัติ (ควรตรวจสอบกับประกาศราชการอย่างเป็นทางการอีกครั้ง เพราะข้อมูลจากบริการภายนอกอาจไม่ครบ 100% โดยเฉพาะวันหยุดชดเชยพิเศษ)
- วันหยุดชดเชย: เมื่อวันหยุดที่เปิดใช้งานตรงวันอาทิตย์ ระบบสร้างวันชดเชยในวันทำการถัดไปให้อัตโนมัติ และแอดมินเลือกปีเพื่อคำนวณย้อนหลังได้ที่เมนู "วันหยุด" ควรตรวจสอบวันตามประกาศทางการก่อนใช้งาน
- ลงเวลาเข้างาน 4 ขั้นต่อวัน: เข้างาน, ออกพักกลางวัน, กลับจากพักกลางวัน และเลิกงาน ต้องสแกนตามลำดับและอยู่ภายในรัศมีร้านทุกครั้ง (ค่าเริ่มต้น 100 เมตร) เช็กอินได้ตั้งแต่ 07:50 น.; สายหลัง 08:00 น. คิด 1 บาทต่อนาที ส่วนกลับจากพักเกิน 60 นาทีคิด 1 บาทต่อนาทีตามเวลาที่เกิน บันทึกเวลา พิกัด GPS ความแม่นยำ ระยะจากร้าน และยอดหัก
- แอดมินดูรายงานลงเวลาได้ที่เมนู "รายงาน" → "ลงเวลาเข้างาน" เลือกวัน/เดือน/ปีและพนักงาน ดูเวลาทั้ง 4 ขั้นและเปิดตำแหน่งแต่ละสแกนบน Google Maps หรือส่งออก Excel ได้
- แจ้งเตือนในแอปด้วยจุดแดง — พนักงานเห็นตัวเลขแดงที่เมนู "หน้าหลัก" เมื่อมีใบลาที่เพิ่งถูกอนุมัติ/ปฏิเสธที่ยังไม่เคยเปิดดู (หายไปเองเมื่อกดเข้าหน้าหลัก)
- แอดมินส่งออกรายงานสรุปวันลาได้ทั้ง **Excel** (ดาวน์โหลดไฟล์ .xlsx ทันที) และ **PDF** (พิมพ์/บันทึกผ่านเบราว์เซอร์) ที่เมนู "รายงาน" — กรองตามช่วงวันที่, สถานะ, ประเภทการลาได้ พร้อมสรุปยอดรวมแต่ละประเภทให้อัตโนมัติ
- **เซ็นอนุมัติออนไลน์ (เฉพาะแอดมิน/ผู้อนุมัติ)** — แอดมินวาดลายเซ็นตัวเองไว้ครั้งเดียวที่เมนู "ข้อมูลของฉัน" ระบบจะนำลายเซ็นไปแปะในช่อง "ผู้อนุมัติ" ของใบลาที่พิมพ์ให้อัตโนมัติทุกครั้งที่กดอนุมัติ/ปฏิเสธ ส่วนฝั่งพนักงานยังคงพิมพ์เอกสารแล้วเซ็นชื่อในช่อง "ผู้ขอลา" ด้วยตนเองตามปกติ
- แอดมินเห็นจุดแดงแจ้งเตือนที่เมนู "อนุมัติ" ตลอดเวลา บอกจำนวนใบลาที่รออนุมัติแบบเรียลไทม์ ไม่ต้องเข้าไปเช็คเอง
- การ์ด "วันนี้ใครลาบ้าง" ขึ้นบนหน้าแรกให้ทั้งพนักงานและแอดมินเห็นทันที ไม่ต้องเข้าปฏิทินเพื่อดู
- ปฏิทินวันลาทีม (ทุกคนดูได้) แตะวันที่มีคนลาหรือวันหยุดเพื่อดูรายละเอียดแบบป๊อปอัพ

## 1) ตั้งค่า Firebase (ทำครั้งเดียว)

1. ไปที่ [console.firebase.google.com](https://console.firebase.google.com) → สร้างโปรเจกต์ใหม่
2. เมนูซ้าย **Build → Firestore Database** → Create database → เลือก production mode → เลือก region (เช่น `asia-southeast1`)
3. เมนูซ้าย **Build → Authentication** → Get started → แท็บ Sign-in method → เปิดใช้งาน **Anonymous**
   (ใช้เป็นตั๋วผ่านเบื้องหลังเท่านั้น พนักงานจะไม่เห็นหน้าจอนี้ ล็อกอินจริงคือหน้าจอ PIN)
4. เมนูซ้าย **Project settings** (รูปเฟือง) → เลื่อนลงมาที่ "Your apps" → กด ไอคอน `</>` เพื่อเพิ่ม Web app → ตั้งชื่อ → จะได้ค่า config มา (apiKey, authDomain ฯลฯ) เก็บไว้ใช้ในขั้นตอนถัดไป
5. ไปที่แท็บ **Rules** ของ Firestore Database → คัดลอกเนื้อหาจากไฟล์ `firestore.rules` ในโปรเจกต์นี้ไปวางแทนของเดิม → Publish

> หมายเหตุ: โปรเจกต์นี้**ไม่ใช้ Firebase Storage** จึงไม่ต้องอัปเกรดเป็น Blaze Plan หรือผูกบัตรเครดิตใดๆ ทั้งสิ้น ไฟล์แนบทั้งหมดถูกบีบอัดแล้วเก็บอยู่ใน Firestore โดยตรง ใช้แผนฟรีของ Firebase ได้เต็มรูปแบบ

## 2) รันบนเครื่องตัวเอง (ทดสอบก่อน deploy)

```bash
npm install
cp .env.example .env
```

เปิดไฟล์ `.env` แล้วกรอกค่าจาก Firebase (ขั้นตอนที่ 1.4) และตั้ง `VITE_SETUP_PIN` เป็นรหัสลับที่คุณจำได้คนเดียว — ใช้ทั้งตอนสร้างแอดมินคนแรก **และ** เป็น "รหัสของบริษัท" ที่พนักงานต้องกรอกตอนลงทะเบียนบัญชีตัวเอง (ดูหัวข้อถัดไป)

หากค่า Firebase ไม่ครบ แอปจะแสดงรายการค่าที่ขาดแทนหน้าจอว่าง ต้องใส่ค่าจริงจาก Firebase ก่อนใช้งานและเริ่ม dev server ใหม่

```bash
npm run dev
```

เปิด `http://localhost:5173` — ระบบจะพาไปหน้า **"ตั้งค่าครั้งแรก"** โดยอัตโนมัติเพราะยังไม่มีพนักงานในระบบ กรอกชื่อ, ตั้ง PIN ของตัวเอง, และใส่ `VITE_SETUP_PIN` ที่ตั้งไว้ → จะได้บัญชีแอดมินคนแรก

**พนักงานคนอื่นไม่ต้องรอให้แอดมินเพิ่มให้ก็ได้** — ที่หน้าเข้าสู่ระบบ (PIN) จะมีลิงก์ **"พนักงานใหม่? ลงทะเบียนที่นี่"** ให้พนักงานกรอกชื่อ, แผนก, ตั้ง PIN ของตัวเอง และกรอก **"รหัสของบริษัท"** (คือค่าเดียวกับ `VITE_SETUP_PIN`) เพื่อยืนยันว่าเป็นคนในบริษัทจริง ระบบจะสร้างบัญชีพนักงาน (สิทธิ์ทั่วไป ไม่ใช่แอดมิน) ให้อัตโนมัติ — แอดมินยังเข้าไปแก้ไขข้อมูล เช่น เพศ, โควตาวันลารายบุคคล ในภายหลังได้ตามปกติที่หน้า "พนักงาน"

ระบบจะสร้างประเภทการลาให้อัตโนมัติ 3 แบบ (ลาป่วย 14 วัน/ปี, ลากิจ 7 วัน/ปี, ลาคลอดบุตร — ไม่ตั้งโควตากลาง เพราะต้องกำหนดเป็นรายบุคคล) ปรับจำนวนวันมาตรฐานได้ที่เมนู **"ประเภทลา"** จากนั้นเข้าเมนู **"พนักงาน"** เพื่อเพิ่มพนักงานคนอื่นๆ ตั้ง PIN ให้แต่ละคน และกำหนดโควตาลาคลอดบุตรเป็นรายบุคคลเมื่อมีคนต้องใช้สิทธิ์

### กำหนดสิทธิ์ข้อมูลเงินเดือน

ข้อมูลเงินเดือนและจำนวนวันทำงานรายงวดถูกแยกเก็บใน `payrollProfiles` และ `payrollRecords` โดย Firestore Rules อนุญาตเฉพาะ Firebase UID ใน allowlist เท่านั้น การ login และข้อมูลพนักงานทั่วไปยังใช้สิทธิ์ Anonymous Auth ตามปกติ แม้ UID ยังไม่ได้ allowlist ก็ยังเข้าระบบและเห็นรายชื่อพนักงานได้

1. Login เป็นแอดมินตามปกติ แล้วคัดลอก UID จากเมนู **พนักงาน** หรือ Firebase Console → Authentication → Users
2. ใน Firestore Console สร้างเอกสาร `meta/payrollAdmins` โดยตั้ง field `uids` เป็น array ของ UID แอดมิน เช่น `['UID ที่คัดลอก']`
3. เผยแพร่ `firestore.rules` ไปยัง Firebase แล้วโหลดแอปใหม่ เพื่อเปิดใช้และย้ายข้อมูลเงินเดือนเดิมเข้า `payrollProfiles`

เพิ่ม UID ของแต่ละอุปกรณ์แอดมินแยกกัน หากออกจากระบบหรือล้างข้อมูลเว็บไซต์ Anonymous UID จะเปลี่ยน ต้องเพิ่ม UID ใหม่ใน allowlist ก่อนใช้หน้าเงินเดือนอีกครั้ง โดยไม่กระทบการ login หรือเมนูพนักงานทั่วไป

## 3) Deploy ขึ้น Netlify

**วิธีที่ง่ายที่สุด — ผ่าน Git:**

1. Push โค้ดโปรเจกต์นี้ขึ้น GitHub/GitLab
2. ไปที่ [app.netlify.com](https://app.netlify.com) → Add new site → Import an existing project → เลือก repo
   Netlify จะอ่านค่า build command และ publish directory จากไฟล์ `netlify.toml` ให้อัตโนมัติ (ไม่ต้องตั้งเอง)
3. ก่อนกด Deploy ให้ไปที่ **Site settings → Environment variables** แล้วเพิ่มตัวแปรทั้งหมดจากไฟล์ `.env` ของคุณ (`VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, ..., `VITE_SETUP_PIN`)
4. กด Deploy — เสร็จแล้วจะได้ลิงก์ เช่น `https://your-app.netlify.app` ที่เปิดจากมือถือเครื่องไหนก็ได้

**วิธีลัด (ไม่ผ่าน Git):**

```bash
npm run build
```

แล้วลากโฟลเดอร์ `dist` ไปวางที่หน้า Netlify Drop ([app.netlify.com/drop](https://app.netlify.com/drop)) — วิธีนี้ยังต้องไปตั้งค่า Environment variables ในภายหลังแล้ว trigger deploy ใหม่ ค่าตัวแปรถึงจะมีผล (เพราะค่าถูกฝังตอน build)

## 4) ใช้งานจากมือถือ

เปิดลิงก์ Netlify จากมือถือ แล้วเลือก "เพิ่มลงหน้าจอโฮม" (Add to Home Screen) จากเบราว์เซอร์ จะได้ไอคอนคล้ายแอป เปิดใช้ได้เร็วเหมือนแอปจริง ข้อมูลจะซิงก์ข้ามอุปกรณ์ทันทีเพราะเก็บบน Firestore แบบเรียลไทม์ (แอดมินอนุมัติจากมือถือ พนักงานเห็นผลอัปเดตทันทีโดยไม่ต้องรีเฟรช)

## โครงสร้างข้อมูล (Firestore)

- **employees** — ชื่อ, PIN, แผนก, สิทธิ์ (employee/admin), โควตาวันลารายบุคคล, สถานะเปิด/ปิดใช้งาน
- **payrollProfiles** — สถานะการจ้าง, เงินเดือน/ค่าแรง, เงินหัก และเบี้ยขยัน (จำกัดด้วย Firebase UID allowlist)
- **payrollRecords** — จำนวนวันทำงานที่แอดมินกรอกในแต่ละงวดเงินเดือน (จำกัดด้วย Firebase UID allowlist)
- **leaveTypes** — ชื่อประเภทลา, จำนวนวันมาตรฐาน/ปี
- **leaveRequests** — ใบลาแต่ละใบ: พนักงาน, ประเภท, ช่วงวันที่, จำนวนวัน, เหตุผล, สถานะ (pending/approved/rejected), ผู้อนุมัติ
- **holidays** — วันหยุดและวันหยุดชดเชยรายปี
- **attendance** — เวลาเข้างาน/ออกพัก/กลับจากพัก/เลิกงาน พร้อมพิกัด ระยะจากร้าน นาทีสาย และยอดหักรายวัน

## หมายเหตุด้านความปลอดภัย

ระบบนี้ใช้ PIN ของบริษัทเองแทนอีเมล/รหัสผ่าน โดยใช้ Firebase Anonymous Auth เป็นตั๋วผ่านเบื้องหลังให้เข้าถึง Firestore ได้ เหมาะกับเครื่องมือใช้งานภายในองค์กรที่ไม่ได้เผยแพร่สู่สาธารณะวงกว้าง หากต้องการความปลอดภัยระดับสูงขึ้น (เช่น ป้องกันการลองสุ่ม PIN จากฝั่ง client จำนวนมากๆ) แนะนำให้ในอนาคตเพิ่ม Cloud Function สำหรับตรวจสอบ PIN ฝั่งเซิร์ฟเวอร์แทน

การลงเวลาในเวอร์ชันนี้คำนวณเวลาสายจากนาฬิกาอุปกรณ์และตำแหน่งจาก GPS ของเบราว์เซอร์ จึงไม่ใช่หลักฐานป้องกันการปลอมแปลงระดับเซิร์ฟเวอร์ หากใช้หักค่าจ้างจริงควรตรวจสอบรายการและย้ายการตรวจเวลา/สิทธิ์ไป Cloud Functions พร้อมปรับ Firestore Rules ให้ผูกกับตัวตนพนักงาน
